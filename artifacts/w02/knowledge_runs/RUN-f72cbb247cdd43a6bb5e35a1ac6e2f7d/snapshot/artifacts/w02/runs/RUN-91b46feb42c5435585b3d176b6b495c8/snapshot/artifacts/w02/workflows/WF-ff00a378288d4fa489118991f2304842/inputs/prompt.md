【最先要遵守的一条：quote 怎么抄】
quote 必须是从原文里逐字复制的 **2 到 4 个汉字**，不含任何标点（引号、顿号、逗号都不行），不换同义词，不省略中间的词，不超出 4 个字。
写超长整句、写成总结、删掉引号、把「找」写成「归」——任何一处对不上，整轮提取立即作废，你前面所有批次的结果一起作废。
所以每次都只抄三四个字：先看原文里哪一小段天然不含标点，照着那几个字抄下来，语义交给 statement 去说。

【第二件要遵守的：三个值只从同一条消息里取】
本批的 transcripts 可能包含两场访谈。你只取**一条**消息作为证据，按这个顺序做：
1）在本批所有 message 里，找 speaker 为 assistant 的；
2）取其中**最后一条**；
3）meeting_id：这条 message 所在那个元素顶端的 meeting_id；
4）message_id：这条 message 自己的 id；
5）quote：从这条 message 的 content 里抄 3 个连续汉字。
三个值必须全来自同一条消息：不能 meeting_id 取这头、message_id 取那头，也不能 quote 取自另一条消息。
不要把本批之外、或另一场访谈里的 id 写进来。

优先整理访谈者列出的 focus_questions 相关陈述，并保留理解这些陈述所需的背景。
区分客户对现状的说法、个人观点和目标、尚待核实的问题。一个条目尽量只表达一项可核对的主张。
同一个术语在不同角色、时间或范围下可能含义不同，保留原文限定，不自行统一。
若原文只提出问题而没有答案，不把问题改写成已经存在的业务规则。

本轮补充要求：
区分「判断」与「结论」：受访者明确声明是个人看法而非核查结论的，原样标注为判断，不得升格为事实或依据。
区分「个人工作记录」与「公司口径」：受访者声明不能作为公司数据使用的材料，标注其效力边界，不得作为口径来源。
「不掌握」「无法确认」「不归我定」不是同一种回答，保留原文措辞，不合并成「未知」一项。
同一件事由多个角色分别陈述时，逐条保留各自说法与限定范围，不在提取阶段判定谁对谁错。
涉及权限、签批、预算的陈述，注意是否属于受访者本人有权决定的范围内，超出其职权的表述标为待确认。

输出规模（本批只要 1 条）：
每批**只输出 1 条候选**，挑本批与本轮 focus_questions 最相关、最有核查价值的那一条，写完立刻结束 JSON。
宁可只给 1 条但引用能原样命中，也不要为了多给而让某条引用被压缩或改写——一条不合格会让整轮提取作废。
claims 必须是**恰好 1 条的数组**，不允许空数组，也不允许 2 条以上。

输出格式的硬性要求：
只输出一个 JSON 对象，顶层只能有 claims 一个键，不得出现 type、properties、required、additionalProperties 等 schema 关键字。
不得附加 note、comment、explanation、reason、summary 之类任何其他顶层键，多一个键整轮作废。
不要复述、不要抄写、不要简介 Schema 本身；收到 schema 说明后直接产出数据。
每条候选必须**同时具备这 8 个字段**，缺一个整轮作废：id、statement、kind、evidence_status、qualifiers、evidence、conflict_ids、review。
其中 review 固定写成 {"status": "pending", "note": ""}，不能省略；conflict_ids 固定写成 []。
evidence_status 只能是 "reported" 或 "unknown"，不要写 verified 或 conflicting。
kind 只能取 fact、opinion、inference、question 之一。
id 只能用英文字母、数字、下划线、点、冒号、连字符，且以字母或数字开头，例如 C-001；**不能用中文**（写「LIN核销归属」会被判废）。
qualifiers 是**字符串数组**，每一项是一句中文说明，例如 ["角色：周老师", "范围：会员表"]；不要写成 {"scope":"live"} 这种键值对，也不要写成 ["scope":"live"]——那不是合法 JSON。
evidence 是数组，每个元素必须有 meeting_id、message_id、quote 三个字段，缺一个整轮作废。

证据引用的硬性要求（校验方式：quote 必须能在该 message 的 content 里原样搜到，否则整轮作废）：
quote 必须是该条 message content 中直接复制的一段连续文字，不允许任何改写。
quote 只允许 **2 到 4 个汉字**，超过 4 字必须再截短。**越短越安全，3 个字最稳。**
**quote 里不允许出现阿拉伯数字、英文、空格**。实测最常踩的坑就是抄「120万」「80万活跃」这类带数字的串——原文写的是「120 万」，中间有空格，你少打一个空格就整轮作废。看到数字就换一段：引那句话里**不含数字**的部分。
**本批优先提取不含数字的陈述。** 以数字为核心的主张（会员数、金额、百分比、几个季度）本阶段一律不提取，留给人工核对——不是不许记，是这一批不记。
**引号也算标点**：原文「会员表里“会员”具体怎么定义」里含引号，不能引这 8 个字；改成引「会员表」或「怎么定义」。
**一个字都不能换**：不得把「找」写成「归」、把「说」写成「讲」、把「要」写成「需要」。同义词替换同样算作废。
**不许跳过中间的词**：原文「连续四个季度在下滑」，写成「连续下滑」就作废——这中间少了「四个季度」，原文里根本没有「连续下滑」这四个字连在一起。
抄 3 个字的正确含义是：原文里**紧挨着的** 3 个字。正确写法是「连续四」「四个季度」「在下滑」这种；错误写法是把两个词各取一半拼起来。
**quote 里不允许出现任何标点符号**：逗号、顿号、句号、引号、括号、冒号、分号，一个都不能有。
如果你选中的那段文字里有标点，说明**你选错了片段**——换一段紧邻的、天然不含标点的短语，而**不是把标点删掉**。
最常见的错法就是删标点：原文「会员表里“会员”具体怎么定义」，写成「会员表里会员」——引号被删掉，这个字串在原文里根本不存在，整轮作废。
quote 不得包含数字、空格、英文和符号；遇到「120 万」「80 万」这类带空格的数字，改引它周围不含数字的短语。
取最能支撑该条主张的那个短语，不要为了完整性搬运整句；宁可短，不可改。
一条候选只引用一个 message 里的一段文字；跨 message 拼接、跨句拼接一律作废。
同一条 quote 不要复用到两条候选。

只能引用受访者的话：speaker 为 assistant 的是受访者，speaker 为 user 的是访谈者。
evidence 里的 quote 只能取自 **speaker 为 assistant** 的 message；访谈者的提问、复述、归纳、确认语都不能当证据。
实在找不到受访者原话的候选，不要勉强：换一条别的陈述，或者按下面的占位写法处理。

meeting_id 与 message_id 必须配对（实测这是第二大错源）：
每次请求里的 transcripts 是一个数组，**可能包含不止一场访谈**；每个元素顶端有它自己的 meeting_id，下面才是 messages。
你填的 meeting_id 必须是**那条 message 实际所在的那个元素**的 meeting_id，message_id 必须是那条消息自己的 id。
反例：把林经理那场的 message_id 配到陈姐那场的 meeting_id 上，整轮作废。
message_id 只能从本次请求里**逐字抄**，不要按编号规律推算、不要补齐中间缺失的号、不要编造。
写完 quote 后回到原文确认：这段文字在不在你填的那个 id 下面？那条 id 在不在你填的那个 meeting_id 下面？两个都对才写。

如果本批只有访谈者的提问、确实找不到任何受访者陈述，不要引用访谈者、也不要留空，按这个方式记一条占位候选：
kind 填 question，evidence_status 填 unknown，evidence 填 []，conflict_ids 填 []，
statement 写本批提问要核实的那个业务主题，qualifiers 写 ["本批仅含访谈者提问，无受访者陈述"]。
