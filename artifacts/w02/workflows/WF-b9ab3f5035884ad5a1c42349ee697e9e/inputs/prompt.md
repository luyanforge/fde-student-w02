优先整理访谈者列出的 focus_questions 相关陈述，并保留理解这些陈述所需的背景。
区分客户对现状的说法、个人观点和目标、尚待核实的问题。一个条目尽量只表达一项可核对的主张。
同一个术语在不同角色、时间或范围下可能含义不同，保留原文限定，不自行统一。
若原文只提出问题而没有答案，不把问题改写成已经存在的业务规则。

本轮补充要求：
区分「判断」与「结论」：受访者明确声明是个人看法而非核查结论的，原样标注为判断，不得升格为事实或依据。
区分「个人工作记录」与「公司口径」：受访者声明不能作为公司数据使用的材料，标注其效力边界，不得作为口径来源。
「不掌握」「无法确认」「不归我定」不是同一种回答，保留原文措辞，不合并成「未知」一项。
同一件事由多个角色分别陈述时，逐条保留各自说法与限定范围，不在提取阶段判定谁对谁错。
涉及权限、签批、预算的陈述，注意是否属于受访者本人有权决定的范围内，超出其职权的表述标为待确认。

证据引用的硬性要求（不满足即整轮作废，校验方式是「quote 必须能在该 message 的 content 里原样搜到」）：
quote 必须是从该条 message content 中直接复制的**一段连续文字**，不允许任何改写。
不得删减中间任何字词、不得跳过并列项、不得用省略号、不得把两句不相邻的话拼在一起。
引号与标点原样照抄：原文用全角就用全角，用半角就用半角，不作替换。
数字与空格的写法必须照抄：原文写「120 万」就不能写成「120万」，原文写「120万」就不能加空格。
长度硬上限 30 个汉字，越短越安全；推荐只引 10 到 20 个字的独特片段。
一条 quote 不得跨越句号、感叹号、问号或换行符，只能取自同一句话之内。
一条候选只引用一个 message 里的一段文字；跨 message 拼接一律作废。

对照示例（以下错法在上一轮实测中真实发生过，都会被判废）：
原文：第二，技术核查由我安排，但走谁的签批、要交问题清单还是字段清单、几个工作日能出结论，这些我现在不作承诺，得看核查对象和接入条件再定。
✗ 错误：技术核查由我安排，但走谁的签批、要交问题清单还是字段清单、几个工作日能出结论，我现在不作承诺（漏掉原文的「这些」）
✓ 正确：技术核查由我安排，但走谁的签批
✓ 正确：这些我现在不作承诺

原文：会员数我说的是系统全量会员数，120 万，这个数和活跃会员不是同一个口径。
✗ 错误：会员数我说的是系统全量会员数，120万（原文「120 万」中间有空格，不能去掉）
✓ 正确：系统全量会员数，120 万
✓ 正确：这个数和活跃会员不是同一个口径

原文：技术核查由我安排……正式的数据权限这次访谈里我不批。
✗ 错误：技术核查我可以安排，接入条件我也能提；安全要求、数据用途或责任没说清楚时，我可以要求先暂缓接入（把两段话拼成一条，且把「由」改成「可以」）
✓ 正确：正式的数据权限这次访谈里我不批
✓ 正确：技术核查由我安排

每条候选输出前做一次逐字比对：把 quote 拿到原文该句里用字符串查找的办法过一遍，搜不到就缩短重写，不允许「大致意思对」的引用。
若某个要点在原文里实在找不到能连续引用的片段，就只引最短的关键字片段（例如「我和运营一起确认会员范围」），不要为了完整性凑长句。
