【第一件事：quote 怎么抄】
每条候选带一条 evidence，其中 quote 必须是从该 message 的 content 里**连续照抄**的一段原文，长度 8 到 25 个字，标点、数字、空格、引号都可以有，但必须**一个字符都不改**：不删字、不添字、不换同义词、不调整顺序、不把两段不相邻的文字拼在一起。
校验方式是死板的：程序拿你写的 quote 去那条 message 里做**子串查找**，查不到就整轮作废，前面所有批次一起作废。
所以顺序必须是「先选中原文的一段 → 原样抄下来」，不是「先想好怎么说 → 再写一段意思对的话」。
quote 只是定位锚点，语义写在 statement 里；不要在 quote 里做任何概括、合并、压缩、补全。

优先整理访谈者列出的 focus_questions 相关陈述，并保留理解这些陈述所需的背景。
区分客户对现状的说法、个人观点和目标、尚待核实的问题。一个条目尽量只表达一项可核对的主张。
同一个术语在不同角色、时间或范围下可能含义不同，保留原文限定，不自行统一。
若原文只提出问题而没有答案，不把问题改写成已经存在的业务规则。

本轮补充要求：
区分「判断」与「结论」：受访者明确声明是个人看法而非核查结论的，原样标注为判断，不得升格为事实或依据。
区分「个人工作记录」与「公司口径」：受访者声明不能作为公司数据使用的材料，标注其效力边界，不得作为口径来源。
「不掌握」「无法确认」「不归我定」不是同一种回答，保留原文措辞，不合并成「未知」一项。
同一件事由多个角色分别陈述时，逐条保留各自说法与限定范围，不在提取阶段判定谁对谁错。
涉及权限、签批、预算的陈述，注意是否属于受访者本人有权决定的范围内，超出其职权的表述标为待确认。

输出格式的硬性要求：
只输出一个 JSON 对象，顶层只能有 claims 一个键，不得出现 type、properties、required、additionalProperties 等 schema 关键字。
claims 是非空数组；不得附加 note、comment、explanation、reason、summary 之类任何其他顶层键，多一个键整轮作废。
不要复述、不要抄写、不要简介 Schema 本身；收到 schema 说明后直接产出数据。
每条候选必须**同时具备这 8 个字段**，缺一个整轮作废：id、statement、kind、evidence_status、qualifiers、evidence、conflict_ids、review。
其中 review 固定写成 {"status": "pending", "note": ""}，不能省略；conflict_ids 固定写成 []；evidence_status 只能是 "reported" 或 "unknown"（本阶段不做核实，不要写 verified 或 conflicting）。
kind 只能取 fact、opinion、inference、question 之一。
id 只能用英文字母、数字、下划线、点、冒号、连字符，且以字母或数字开头，例如 C-001；**不能用中文**（写「LIN核销归属」会被判废）。
qualifiers 是**字符串数组**，每一项是一句中文说明，例如 ["角色：周老师", "范围：会员表"]；不要写成 {"scope":"live"} 这种键值对。
evidence 数组里每个元素必须同时有 meeting_id、message_id、quote 三个字段，缺一个整轮作废。

证据引用的硬性要求：
只能引用受访者的话：speaker 为 assistant 的是受访者，speaker 为 user 的是访谈者。quote 只能取自 assistant 的 message。
访谈者自己的提问、复述、归纳、确认语都不能当证据；访谈者把话说得更清楚也不能引他。
实在找不到受访者原话的候选，不要建这一条，不要拿访谈者的话顶上。
meeting_id 与 message_id 必须来自同一条消息：meeting_id 是该 message 所属那场访谈的 id，message_id 是那条消息自己的 id，两者不可跨会混用。
本批的 transcripts 可能包含**不止一场访谈**：每个元素顶端有它自己的 meeting_id，下面才是 messages。填 meeting_id 时，回到那条 message 所在的那个元素去抄，不要一律用数组里第一个 meeting_id。
message_id 只能从本次请求里**逐字抄**，不要按编号规律推算、不要补齐中间缺失的号、不要编造。
同一条 quote 不要复用到多条候选；多个主张出自同一句话时，分别引那句话里不同的片段。
一条候选只引用一个 message 里的一段连续文字；跨 message 拼接与跨句拼接一律作废。

输出规模：
每批给出 6 到 15 条候选，覆盖本批最值得记录的事实、口径、限制与待核实问题；不要为了凑数而重复同一件事。
同一句话只建一条候选；内容相近的合并成一条。
如果本批确实只有访谈者的提问、没有任何可引的受访者陈述，不要引用访谈者、也不要留空，按这个方式记一条占位候选：
kind 填 question，evidence_status 填 unknown，evidence 填 []，conflict_ids 填 []，
statement 写本批提问要核实的那个业务主题，qualifiers 写 ["本批仅含访谈者提问，无受访者陈述"]。

交付前自检（这一步不能省）：
逐条回看每个 quote，到原文里找出它，确认三件事：① 这段文字在原文里连续存在、一字不差；② 它属于你填的那个 message_id；③ 那条 message 属于你填的那个 meeting_id。
任何一条过不了，就回到原文重新抄一遍，或者删掉这条候选。宁可少给几条，也不能有一条引用对不上。
