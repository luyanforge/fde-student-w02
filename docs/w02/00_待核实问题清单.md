# W02 待核实问题清单

> 版本：v1｜2026-10-31｜依据：旧项目结项 PPT（4 页）、背景补充、本周访谈角色表、W01 已提交 fit-gap（`artifacts/w01/product_fit_gap.json`，11 条 GAP）。
> 用途：本周访谈的输入清单。**不是访谈结论**，全部条目的当前状态均为"未核实"。

## 0. 先下一个判断：旧材料本身的信息缺口

通读结项 PPT 后，第一个发现不是内容问题，而是**结构问题**：

| 应有的项目档案要素 | PPT 中是否存在 |
| --- | --- |
| 上线范围（哪些门店、哪些角色） | 无 |
| 使用率／活跃度数字 | 无 |
| 验收标准与验收结论 | 无（只写"后续工作方向"） |
| 工期、预算、变更次数 | 无 |
| 签批人、结项状态 | 无（只有"阶段结项汇报"标题） |

一份"阶段结项汇报"中**没有任何一个数字**，也没有验收结论和签批记录。这意味着：上一期的"结项"性质（正常通过／带条件通过／暂停）**目前无法判断**，而它直接影响本期立项前提。这是本周访谈需要优先问清的一件事。

PPT 三句原文（已剥除排版）：

- p2「需求完善带动方案持续调整」：根据业务反馈持续调整需求，推动方案逐步完善。业务反馈 → 需求调整 → 方案完善。
- p3「使用推广仍需业务协同」：一线使用——日常使用仍需持续推进；操作方式——继续结合实际工作完善操作路径。
- p4「下一阶段围绕使用与效果持续完善」：操作路径、业务使用（持续跟踪）、效果观察（结合运营工作观察效果）。**以上为后续工作方向。**

三句都是**过程描述**，没有主语、没有数量、没有时点。每一句都能拆出可核实的问题。

## 3. 需要交叉核实的分歧候选（至少选 1 组写进作业）

判定纪律：**共同未知不算冲突；相同说法不算冲突；互补信息不算冲突。** 下面四组是"同一业务问题、可能有不同说法"，是否成立要在访谈后按时间、范围、含义先比对。

| 编号 | 同一业务问题 | 可能的说法差异 | 交叉核实方式 |
| --- | --- | --- | --- |
| D-1 | 复购率到底是不是在跌、怎么算 | 沈总：连续四个季度下滑（无准数）；老周：有系统口径但可能只覆盖线上；小林：按"回头客"体感判断 | 先各自独立问定义，再比对分子分母与统计周期是否同一件事 |
| D-2 | 名单从生成到触达，谁负责执行 | 小林：运营出名单、门店执行；陈姐：门店人力不足、没接到明确要求 | 分别问"最近一次类似名单是怎么落到人头的"，取具体事件而非表态 |
| D-3 | 上期平台有没有被用起来 | 老周：系统有登录/操作记录；陈姐：门店仍用 Excel/微信；沈总：没看到结果 | 要具体数字与具体门店，不接受"在用/没用"的整体判断 |
| D-4 | "80 万活跃会员"的口径 | 老周：系统口径（如近 N 天有交易）；王经理：有贡献收入的口径 | 问出定义与取数系统，比对是否同一批人 |

## 4. 目前明确保留为"未知"的项（不得补成结论）

- 会员、订单、退款三份数据的可得性与覆盖区间。
- 客户是否允许数据出客户环境、脱敏要求由谁定。
- 门店 KPI 是否包含会员复购，触达动作是否有考核或奖惩。
- 上期的验收结论与结项性质（见 V-01）。
- 本期预算、合同与交付范围（背景补充已明确：沈总的说明**不表示**本期预算/范围已确认）。

## 5. 使用方式

1. 本清单作为访谈提纲的问题来源（见 `01_访谈提纲.md`），不直接粘贴给访谈对象。
2. 访谈后逐条回填：`已核实 / 部分核实 / 仍未知 / 与 W01 冲突`，并记录来源定位（会议号 + 消息号）。
3. 回填结果进入 `interview_notes.md` 的"重要信息的核查与取舍"一节；影响 W01 判断的条目在 `product_fit_gap.json` 上按原编号修订。
